# 参数搜索提速方法论

## 核心原则：粗→细两阶段搜索

参数遍历不要一步到位用细粒度全量搜索，而是分两阶段：

1. **阶段1（粗筛）**：大步长、少组合，快速扫描全局趋势，判断每个参数的影响方向和大致最优区间
2. **阶段2（细筛）**：在粗筛发现的最优区域附近加密搜索，确认精确最优值

### 为什么这样做

- 粗筛用 1/3~1/5 的组合数覆盖全参数空间，快速排除无效区域
- 细筛只在有希望的区域搜索，避免在无效区域浪费算力
- 总时间通常比全量搜索节省 50%+，且不会错过关键趋势

### 脚本模板

```python
# ==================== 🔧 执行阶段切换 ====================
PHASE = 1  # 改为 2 进入细筛阶段

# ==================== 阶段1：粗筛 ====================
if PHASE == 1:
    batch = {
        "param_a": [10, 50, 100],        # 大步长：3个采样点覆盖全范围
        "param_b": [0.1, 0.5],            # 两端探测
    }

# ==================== 阶段2：细筛 ====================
elif PHASE == 2:
    # 根据阶段1结果：假设 param_a=50 附近最优，param_b=0.1 更好
    batch = {
        "param_a": [30, 40, 50, 60, 70],  # 在最优附近加密
        "param_b": [0.05, 0.08, 0.1, 0.12, 0.15],
    }
```

### 粗筛设计技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| **两端探测** | 只测最小和最大值，判断单调趋势 | `[0.1, 0.9]` |
| **大步长** | 等间距采样3~4个点 | `[60, 120, 180]` |
| **关键值+边界** | 包含当前值和两端 | `[0.05, 0.1(当前), 0.2]` |
| **离散值全测** | 离散参数（如 hold_period）值少可全测 | `["3D", "5D", "W", "10D"]` |

## 参数搜索时间估算

### 单组回测耗时参考

| 变更类型 | 改了哪层 | 是否需要重算因子 | 单组耗时 |
|----------|----------|----------------|---------|
| 仅改 select_num / offset / cap_weight | config 层 | ❌ | ~30秒 |
| 仅改过滤阈值（val/pct/rank规则） | config 层 | ❌ | ~30秒 |
| 仅改排序方向/权重（args） | config 层 | ❌ | ~30秒 |
| 仅改策略文件中的选股逻辑（排名组合、过滤公式等） | 策略文件层 | ❌ | ~30秒 |
| 改因子参数（第3位/第2位） | 因子层 | ✅ | ~5-7分钟 |
| 改 hold_period | 因子层 | ✅ | ~5-7分钟 |
| 改 rebalance_time | 因子层 | ✅ | ~5-7分钟 |
| 改定风波择时因子时间点（第5位） | 因子层 | ✅ | ~5-7分钟 |
| 新增从未计算过的因子 | 因子层 | ✅ | ~5-7分钟 |

**关键理解**：策略文件（`策略库/*.py`）中的 `calc_select_factor()` 只操作已计算好的因子数据，
不会触发因子重算。所以修改策略文件中的复合因子公式、排名方式、分位数阈值等，
和修改 config 中的过滤规则一样，都走快速路径（~30秒/组）。

### 并行化

- `run_backtest_multi` 的 `boost=True` 启用并行处理
- 有效并行度 ≈ `n_jobs`（通常 `cpu_count() - 3`）
- 实际加速比约 n_jobs 的 60~80%（有调度和IO开销）

### 时间估算公式

```
总时间 ≈ 初始化时间 + (需重算组合数 / n_jobs) × 单组重算时间
        + (不需重算组合数 / n_jobs) × 30秒
```

## 参数搜索维度排序

按照对回测速度的影响，优先搜索快速参数：

### 推荐的搜索顺序

```
1. 快速参数先行（不需重算因子）
   - select_num, 市值filter阈值, 过滤规则阈值, 排序权重
   - 这些改动只需选股+模拟，30秒/组，可以大量搜索

2. 慢速参数后行（需要重算因子）
   - hold_period, 因子窗口参数, rebalance_time
   - 这些改动需要完整因子计算，5-7分钟/组，应控制组合数

3. 组合验证最后
   - 择时信号引入、因子组合ablation
   - 在前面参数基本确定后再做
```

### ⚠️ 特别注意：hold_period 搜索

hold_period 变更需要重新计算因子（因为周期转换不同），所以：
- 不要和其他慢速参数做笛卡尔积（如 hold_period × 因子参数 = 组合爆炸）
- 建议**单独搜索 hold_period**，先锁定最优周期，再搜其他参数
- 或者只测 2~3 个候选周期（如 `["3D", "5D", "W"]`），不要穷举

### ⚠️ 特别注意：rebalance_time 搜索

rebalance_time 变更也需要重新计算，且必须注意：
- 使用定风波择时时，rebalance_time 必须比择时因子时间晚10分钟
- rebalance_time 和择时因子时间点应联动搜索，不要分开
- 建议只测 3~4 个时间档位（如 `["0940-0940", "0945-0945", "0950-0950"]`）

## 搜索结果分析要点

### 判断是否过拟合

1. **参数平原性**：最优参数附近的参数表现是否稳定？如果微调就大幅下降，可能过拟合
2. **单调趋势**：如果某参数呈现明显单调趋势（越大/越小越好），说明当前搜索范围可能不够，需要扩展
3. **年度稳定性**：最优参数在各个年度是否都表现良好？还是仅在某些年度突出？

### 粗筛后如何决定细筛范围

```
粗筛结果趋势 → 细筛策略：
- 明显最优峰值 → 在峰值两侧加密（如 best±20%）
- 单调递增/递减 → 向最优方向扩展搜索范围
- 平坦无差异 → 该参数不敏感，保持默认值，不需细筛
- 两个候选峰值 → 分别在两个峰值附近细筛
```

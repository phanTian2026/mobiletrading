# 未来函数防范规则（COIN｜币圈）

## 核心原则

**用于“下单决策”的数据时间必须 ≤ 交易执行时间**。

生活类比：考试只能用开考前发下来的资料；如果你在第 1 题就翻到第 10 题答案，分数当然虚高，但现实里做不到。

在 K 线回测里，把它具体化成一句话：

- 如果你在某根 K 线的开盘/收盘做决策，那么因子/信号只能使用这根及更早的 K 线信息，不能用下一根（未来）的任何数据。

## 最常见的“穿越”来源（从高频到低频）

1. **忘了 shift**：用当根 K 线收盘价算出的信号，却在同一根 K 线“开盘”成交。
2. **rolling 的右端偷看**：用包含当前 bar 的 rolling 结果，却把它当成上一个时点可用。
3. **合并外部数据没对齐**：例如资金费率/市值/供给等数据的时间戳对齐错误，导致把未来一条合并进来。

## 最小检查清单（每次写/改因子都过一遍）

- 你策略的“成交价”用的是哪一列？例如 `avg_price_1m` 或 K 线 `open/close`。
- 你因子/信号在什么时点生成？是“用收盘算、下一根开盘下单”，还是“用开盘前可得数据算、当根开盘下单”？
- 如果是“用收盘算、下一根开盘下单”：任何用于排序/过滤/开仓的因子列，必须 `shift(1)` 后再用。

## 代码层面的安全写法（示例）

### 场景 A：用收盘价计算信号，下一根K线开盘执行

```python
# 先算信号（基于 close）
df['sig_raw'] = df['close'].pct_change(24)

# 再把信号整体后移 1 根，表示“下一根才拿得到”
df['sig'] = df['sig_raw'].shift(1)
```

### 场景 B：用 rolling 计算，不想包含当前这根（避免右端偷看）

```python
roll = df['close'].pct_change().rolling(24, min_periods=24)
df['up_ratio_raw'] = roll.apply(lambda x: (x > 0).sum() / (len(x) + 1e-8), raw=False)
df['up_ratio'] = df['up_ratio_raw'].shift(1)
```

## 外部数据对齐（coin-cap / funding / btc 对照）

- 合并外部数据时，必须确认时间戳粒度与 K 线一致，并确保是“过去→现在”对齐。
- 如果外部数据是日频，而 K 线是 1H：需要明确“当天数据何时可得”，否则默认只能从次日开始使用。

## 结果层面的报警信号

- 策略胜率异常高、回撤极低、几乎不亏损：优先怀疑穿越。
- 新增一个因子后收益暴涨：先做最短周期冒烟回测 + 检查信号 shift/对齐，再谈调参。

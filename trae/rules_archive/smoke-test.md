# Smoke Test 规则 — 长时间脚本预验证

## 核心原则

> **任何预计运行 >10 分钟的脚本，执行前必须先跑 Smoke Test。**
> Smoke Test 必须在 1-3 分钟内完成，验证全链路无报错后再启动正式运行。

## 为什么需要 Smoke Test

- AI 生成的优化脚本可能有配置错误、路径错误、参数格式错误
- 一个 3 小时的任务如果在第 2 小时报错，浪费巨大
- 大多数 bug 在前 1 分钟就会暴露（数据加载、因子缺失、配置解析）
- Smoke Test 走完整代码路径，只是数据量极小

## Smoke Test 三板斧

### 1. 缩短日期范围

将回测日期缩短到 **2-3 个月**，数据量约为全量的 1/50：

```bash
# ❌ 正式运行（8年数据，~5-7分钟/组）
python 回测主程序_增强版.py -name config_xxx -s 2016-01-01 -e 2024-12-31

# ✅ Smoke Test（2个月数据，~30秒-1分钟）
python 回测主程序_增强版.py -name config_xxx -s 2024-10-01 -e 2024-12-31
```

### 2. 减少参数组合

参数遍历脚本中，只保留 **1-2 个组合** 验证代码能跑通：

```python
# ❌ 正式 batch（50+组合）
batch = {
    "select_num": [3, 5, 8, 10, 15],
    "threshold": [0.7, 0.8, 0.85, 0.9, 0.95],
}  # 25 组合

# ✅ Smoke Test batch（2组合）
batch = {
    "select_num": [3, 10],    # 取首尾各一个
    "threshold": [0.8],       # 固定一个
}  # 2 组合
```

### 3. 验证输出

Smoke Test 完成后，检查：
- ✅ 进程退出码 == 0
- ✅ 结果文件已生成（`最优参数.xlsx` 或资金曲线文件）
- ✅ 结果数据合理（累积净值 > 0，没有 NaN）

## Smoke Test 实施模板

### 对于 `回测主程序_增强版.py`

```bash
# Step 1: Smoke Test
python 回测主程序_增强版.py -name config_xxx -s 2024-10-01 -e 2024-12-31

# Step 2: 检查退出码
# 如果失败 → 修复 → 重新 Smoke Test
# 如果成功 ↓

# Step 3: 正式运行
python 回测主程序_增强版.py -name config_xxx -s 2016-01-01 -e 2024-12-31
```

### 对于 `寻找最优参数.py`（自定义脚本）

在脚本中添加 Smoke Test 开关：

```python
# ==================== Smoke Test 控制 ====================
SMOKE_TEST = True  # 设为 False 进入正式运行

if SMOKE_TEST:
    # Smoke Test：极简参数，快速验证全链路
    START_DATE = "2024-10-01"
    END_DATE = "2024-12-31"
    batch = {
        "param_a": [batch_full["param_a"][0]],    # 只取第一个值
        "param_b": [batch_full["param_b"][0]],    # 只取第一个值
    }
else:
    # 正式运行：完整参数
    START_DATE = "2016-01-01"
    END_DATE = "2024-12-31"
    batch = batch_full
```

### 对于策略文件修改（策略库/*.py）

```bash
# Step 1: 用最短日期跑一次，验证策略文件语法和逻辑
python 选股+回测.py -name config_xxx -s 2024-10-01 -e 2024-12-31

# Step 2: 确认无报错后，跑正式时间段
python 选股+回测.py -name config_xxx -s 2016-01-01 -e 2024-12-31
```

## 过夜任务的 Smoke Test 流程

过夜任务（`tools/overnight/`）执行前，**必须验证每个任务的 Prompt 能生成可运行的脚本**：

```
睡前流程:
┌─────────────────────────────────────────┐
│ 1. 编写 Prompt → Copilot 生成脚本/配置  │
│ 2. Smoke Test（SMOKE_TEST=True, 1-3 分钟）│
│    ├── 通过 → 继续                      │
│    └── 失败 → 修复 → 重新 Smoke Test    │
│ 3. 切换为正式模式（SMOKE_TEST=False）    │
│ 4. 启动过夜运行                         │
└─────────────────────────────────────────┘
```

## 必须 Smoke Test 的场景

| 场景 | 必须？ | 原因 |
|------|--------|------|
| 新建/修改 config 文件后首次回测 | ✅ 必须 | 配置格式、因子名称可能写错 |
| 新建/修改参数遍历脚本 | ✅ 必须 | 参数路径、batch 格式可能有误 |
| 修改策略文件后首次运行 | ✅ 必须 | 语法错误、列名不存在等 |
| 新增因子后首次计算 | ✅ 必须 | 因子文件可能缺 fin_cols 或语法错 |
| 过夜自动优化任务 | ✅ 必须 | 无人值守，必须确保能跑通 |
| 只改过滤阈值/权重（已验证过的配置） | ❌ 可选 | 低风险变更 |

## Smoke Test 日期选择建议

| 目的 | 推荐日期范围 | 预计耗时 |
|------|-------------|---------|
| 最快验证（语法+加载） | 2024-11-01 ~ 2024-12-31 | ~30 秒 |
| 标准验证（含完整周期） | 2024-10-01 ~ 2024-12-31 | ~1-2 分钟 |
| 稳妥验证（含不同市场环境） | 2024-06-01 ~ 2024-12-31 | ~2-3 分钟 |

**选 2024 年末数据的原因**：最新数据最容易暴露数据路径问题和数据完整性问题。

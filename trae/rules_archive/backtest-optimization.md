# 回测加速策略

## 核心原理：config vs 因子 vs 策略文件 三层分离

回测框架分为三层（完整技术规范见 [`framework-technical-spec.md`](./framework-technical-spec.md)）：

```
config（配置层）→ 因子库（因子计算层）→ 策略库（选股逻辑层）→ 选股+模拟
```

**关键理解**：因子计算是最耗时的环节，但因子数据一旦计算完成就会缓存。
只要因子不变，无论怎么改策略文件（`策略库/*.py`）中的选股逻辑，都只需要重新选股+模拟，非常快。

## 三种速度等级

| 等级 | 改了什么 | 需要执行 | 耗时 |
|------|----------|----------|------|
| 🐢 慢 | **因子层**：新增因子、改因子参数、改 hold_period/rebalance_time/择时时间点 | 在 `config.py` 中让 `running_mode` 覆盖 STEP2（如 `[1, 2, 3, 4]`），运行 `回测主程序.py`（会重算因子） | ~5-7分钟/组 |
| ⚡ 快 | **配置层**：改过滤阈值、排序方向、权重、select_num、offset 等 | 在已有因子缓存的前提下，将 `running_mode = [3, 4]`，运行 `回测主程序.py`（只重跑选股+资金曲线） | ~30秒/组 |
| ⚡ 快 | **策略文件层**：改 `策略库/*.py` 中的选股逻辑（因子组合方式、排名公式等） | 同上：`running_mode = [3, 4]`，运行 `回测主程序.py`（不重算因子） | ~30秒/组 |

## 策略文件修改 = 快速路径 ⚡

**核心规则：策略文件（`策略库/*.py`）只处理已经计算好的因子数据，不触发因子重算。**

策略文件的 `calc_select_factor()` 函数接收的 `df` 已经包含了所有计算好的因子列。
策略文件只是对这些列做排名、组合、过滤等操作。因此：

```python
# 以下对策略文件的修改都不需要重算因子，走快速路径：

# ✅ 快：修改复合因子的组合方式
df['复合因子'] = df['因子A_排名'] + df['因子B_排名']  # 改为：
df['复合因子'] = df['因子A_排名'] * 0.5 + df['因子B_排名'] * 0.5 + df['因子C_排名']

# ✅ 快：修改分位数过滤阈值
df = df[df[f'{volatility.col_name}_排名'] <= 0.7]  # 改为 0.8

# ✅ 快：增删参与排名的因子（只要config中已声明且已计算过）
# 比如注释/取消注释某个因子的排名参与

# ✅ 快：修改排名方式（ascending、method 等）
df.groupby('交易日期')[col].rank(ascending=True, method='min')  # 改为 False
```

**前提条件**：策略文件中使用的因子列必须已经在 config 的 factor_list 中声明过，
且之前已经通过 `running_mode` 覆盖 STEP2 的方式（如 `[1, 2, 3, 4]`）执行过 `回测主程序.py`，完成因子计算并缓存。

## 需要重新计算（慢路径 🐢）的变更

以下修改会导致因子数据需要重新计算：

```python
# 1. 选股因子：改变因子名或第3位参数
('n日涨停统计', False, 2, 4)  # 改变 'n日涨停统计' 或 2 → 🐢 必须重新计算
                               # 改变 False 或 4 → ⚡ 不需要重新计算

# 2. 过滤因子：改变因子名或第2位参数
("窗口最低价比值", 10, "val:>1.01")  # 改变 '窗口最低价比值' 或 10 → 🐢 必须重新计算
                                      # 改变 "val:>1.01" → ⚡ 不需要重新计算

# 3. hold_period 变更（周期转换不同，因子需重新聚合）
'hold_period': '5D'  # 改为 '3D' 或 'W' → 🐢 必须重新计算

# 4. rebalance_time 变更（数据对齐方式不同）
'rebalance_time': '0940-0940'  # 改为 '0945-0945' → 🐢 必须重新计算

# 5. 定风波择时因子的时间点变更（需加载不同的分钟数据）
("开盘至今涨幅", False, None, 1, "0935")  # 改为 "0945" → 🐢 必须重新计算
```

## 不需要重新计算（快路径 ⚡）的变更

以下修改不影响因子数据，只需重新选股+模拟：

**config 层修改：**
- 修改过滤因子的过滤规则（如 `val:>1.01` → `val:>1.05`）
- 修改选股因子的排序方向（True/False）
- 修改选股因子的权重（第4位 args）
- 修改 `select_num`（选股数量）
- 修改 `offset_list`
- 修改 `cap_weight`（资金占比）
- 添加/删除/调整 factor_list 中已计算过的因子组合
- 添加/删除/调整 filter_list 中已计算过的因子组合

**策略文件层修改（`策略库/*.py`）：**
- 修改复合因子的排名组合公式
- 修改策略文件中的分位数过滤阈值
- 增删参与复合因子的因子（前提：因子已在 config 中声明并计算过）
- 修改排名方式、排序方向
- 任何不涉及新因子计算的策略逻辑变更

## 判断规则速查

| 修改内容 | 需要执行 | 速度 |
|---|---|---|
| 新增从未计算过的因子 | `running_mode` 覆盖 STEP2（如 `[1, 2, 3, 4]`）运行 `回测主程序.py` | 🐢 慢 |
| 修改因子的参数（第3位/第2位） | 同上：包含 STEP2 的分步执行 | 🐢 慢 |
| 修改 hold_period | 同上：包含 STEP2 的分步执行 | 🐢 慢 |
| 修改 rebalance_time | 同上：包含 STEP2 的分步执行 | 🐢 慢 |
| 修改定风波择时因子的时间点（第5位） | 同上：包含 STEP2 的分步执行 | 🐢 慢 |
| 数据更新（新的交易日数据） | 同上：包含 STEP2 的分步执行 | 🐢 慢 |
| 修改过滤阈值（val/pct/rank） | 在已有因子缓存基础上，将 `running_mode = [3, 4]` 运行 `回测主程序.py` | ⚡ 快 |
| 修改排序方向/权重 | 同上：`running_mode = [3, 4]` | ⚡ 快 |
| 增删已计算过的因子 | 同上：`running_mode = [3, 4]` | ⚡ 快 |
| 修改选股数量/offset/cap_weight | 同上：`running_mode = [3, 4]` | ⚡ 快 |
| **修改策略文件中的选股逻辑** | 同上：`running_mode = [3, 4]` | ⚡ 快 |

## 🚀 批量因子探索的最优流程

当需要探索大量因子（如30个）时：

### 第一步：一次性计算所有候选因子
把所有要探索的因子都加入 config 的 factor_list 和 filter_list 中：

```python
# 把所有候选因子都放进来，一次性计算
"factor_list": [
    ("因子A", False, 参数1, 1),
    ("因子B", True, 参数2, 1),
    # ... 所有30个候选因子
],
"filter_list": [
    ("过滤因子X", 参数1, "val:>0"),
    ("过滤因子Y", 参数2, "pct:<0.5"),
    # ... 所有候选过滤因子
],
```

然后在 `config.py` 中设置 `running_mode = [1, 2, 3, 4]`，执行一次 `回测主程序.py`，所有因子数据都会被计算并缓存。

### 第二步：快速迭代测试
之后每次调整（修改策略文件中的选股逻辑、增删因子组合、修改过滤阈值、调整权重等），
只需在已有因子缓存基础上将 `running_mode = [3, 4]`，执行 `回测主程序.py`：

```bash
# 修改 config 或策略文件 → 只跑选股 + 资金曲线（不重算因子）
python 回测主程序.py
```

这样每次迭代只需选股+模拟（约原来 1/5 的时间），可以快速验证不同因子组合的效果。

## 参数搜索耗时估算

### 单组回测耗时参考

| 变更类型 | 改了哪层 | 是否需要重算因子 | 单组耗时 |
|----------|----------|----------------|---------|
| 仅改 select_num / offset / cap_weight | config 层 | ❌ | ~30秒 |
| 仅改过滤阈值（val/pct/rank规则） | config 层 | ❌ | ~30秒 |
| 仅改排序方向/权重（args） | config 层 | ❌ | ~30秒 |
| 仅改策略文件中的选股逻辑（排名组合、过滤公式等） | 策略文件层 | ❌ | ~30秒 |
| 改因子参数（第3位/第2位） | 因子层 | ✅ | ~5-7分钟 |
| 改 hold_period | 因子层 | ✅ | ~5-7分钟 |
| 改 rebalance_time | 因子层 | ✅ | ~5-7分钟 |
| 改定风波择时因子时间点（第5位） | 因子层 | ✅ | ~5-7分钟 |
| 新增从未计算过的因子 | 因子层 | ✅ | ~5-7分钟 |

**关键理解**：策略文件（`策略库/*.py`）中的 `calc_select_factor()` 只操作已计算好的因子数据，
不会触发因子重算。所以修改策略文件中的复合因子公式、排名方式、分位数阈值等，
和修改 config 中的过滤规则一样，都走快速路径（~30秒/组）。

### 并行化

- `run_backtest_multi` 的 `boost=True` 启用并行处理
- 有效并行度 ≈ `n_jobs`（通常 `cpu_count() - 3`）
- 实际加速比约 n_jobs 的 60~80%（有调度和IO开销）

### 时间估算公式

```
总时间 ≈ 初始化时间 + (需重算组合数 / n_jobs) × 单组重算时间
        + (不需重算组合数 / n_jobs) × 30秒
```

### 参数搜索耗时示例

假设 n_jobs=8，执行50组参数搜索：

| 组合类型 | 组合数 | 单组耗时 | 总时间（估算） |
|----------|--------|---------|----------------|
| 全部快速路径 | 50 | 30秒 | ~4-5分钟 |
| 10组需重算 + 40组快速 | 50 | 6分钟/30秒 | ~12-15分钟 |
| 全部需重算 | 50 | 6分钟 | ~45-60分钟 |

## 调试与开发模式

### 分步调试

通过修改 `config.py` 中的 `running_mode` 实现快速迭代。每个数字对应一段“流水线上的工序”，只跑你关心的那一步：

- **数据问题**：`running_mode = [1]` → 对应执行 `program/step1_整理数据.py` → 检查 `data/运行缓存/` 中的清洗后数据
- **因子问题**：`running_mode = [2]` → 对应执行 `program/step2_计算因子.py` → 检查因子值分布和截面相关性
- **选股问题**：`running_mode = [3]` → 对应执行 `program/step3_选股.py` → 检查选股结果是否符合预期
- **绩效问题**：`running_mode = [4]` → 对应执行 `program/step4_实盘模拟.py` → 在已有选股结果基础上快速调整手续费/滑点

常见用法示例：

- 首次全流程跑通：`running_mode = [1, 2, 3, 4]`
- 调整因子逻辑但数据不变时，只重算因子：先确保已经跑过 STEP1，再设置 `running_mode = [2]`
- 调整选股逻辑但因子不变时，只重跑选股：先确保已经跑过 STEP1、2，再设置 `running_mode = [3]`
- 只想看交易结果和资金曲线（不改选股）：先确保已经有选股结果，再设置 `running_mode = [4]`

### 性能优化

- `performance_mode = "ECO" | "BAL" | "MAX"`：控制 `n_jobs` 与 `factor_col_limit`，在“更省内存”和“更快速度”之间平衡
- **缓存机制**：STEP1–3 的结果都会落盘缓存，下次只改后面步骤时可以直接复用前面的结果
- **内存管理**：因子计算按列分片（通过 `factor_col_limit` 控制），避免一次性生成过多列导致内存占用过高

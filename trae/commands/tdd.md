# TDD（测试驱动开发）命令

调用 tdd-guide 角色，按固定流程推进开发。

## 什么时候用

- 写新功能/新函数
- 修 bug（先写能复现 bug 的测试）
- 重构（先用测试把行为“钉住”）

## 固定流程

1. 先定义输入/输出（接口/函数签名/数据结构）
2. 先写测试并让它失败（RED）
3. 写最小实现让测试通过（GREEN）
4. 重构代码但保持测试一直通过（REFACTOR）
5. 检查覆盖率并补齐（目标 ≥ 80%）

## 最小示例（Python）

```
用户：/tdd 写一个函数：计算某个因子分数

助手（tdd-guide）：
1) 先写 test_*.py：覆盖正常输入 + 边界情况
2) 跑 pytest：确认先失败（红）
3) 写最小实现：让 pytest 通过（绿）
4) 重构：抽常量/拆函数/提升可读性，但 pytest 仍全绿
5) 跑覆盖率：不足就补测试
```
